## Часть 1. ВВЕДЕНИЕ В КОД
### 1. Область применения и реализованный функционал

&nbsp; Данный код находится в активной разработке, поэтому область применения кода сравнительно невелика, так как не реализован геометрический модуль программы. Так доступен анализ только бесконечных гетерогенной сред без выраженной геметрии. Однакоприсутствие транспортного модуля позволяет использовать данную программу в образовательных целях, так как можно отслеживать движение одного нейтрона. Но самое главное можно отслеживать изменение характеристик в зависимости от температуры и отследить, как различные методы справляются с реализацией доплер эффекта.

&nbsp; Текущая программа представляет компактное исследовательское транспортное ядро и поддерживает следующие возможности:

*	перенос отдельных историй нейтронов методом Монте-Карло;
*	непрерывная зависимость от энергии нейтрона;
*	материалы, состоящие из нескольких нуклидов;
*	табличные микроскопические сечения при нескольких температурах;
*	линейную интерполяцию сечений по энергии;
*	выбор нуклида по макроскопическим сечениям;
*	выбор реакции по микроскопическим сечениям;
*	упругое рассеяние с учетом теплового движения ядра;
*	поглощение нейтрона;
*	Doppler broadening в реализации, основанной на используемой в исходном коде NJOY-подобной формулировке;
*	подготовку адаптивной энергетической сетки и температурного разложения для On-The-Fly обработки по MCNP-подобной схеме;
*	Target Motion Sampling (TMS) в Serpent-подобной постановке;
*	расчет простых интегральных характеристик истории;
*	тестовый режим с радиально изменяющейся температурой среды.

### 4. Краткий обзор функционала программы

&nbsp;Главная программа загружает ядерные данные, создаёт массив нейтронных историй и для каждой активной истории повторяет вызов `collision_controller`. Внутри `collision controller` вычисляются сечения, выбираются нуклид и реакция, затем вызывается соответствующая физическая модель.

Концептуально транспортный шаг выглядит так:

```text
source neutron
      |
      v
collision_controller
      |
      +--> total macroscopic XS for each nuclide
      +--> sample nuclide
      +--> reaction microscopic XS
      +--> sample reaction
                |
                +--> scattering --> updated particle state
                |
                +--> absorption --> is_died = true
      |
      v
next collision or history termination
```
&nbsp;Также в программе релиазованы методы построения эффективного сечения взаимодействия :  
* Метод реализованный в коде NJOY на основе SIGMA_1  
* Метод реализованный в коде MCNP работающий на лету (OTF) 

&nbsp;Также реализован метод учета Доплер эффекта с помощью модуля Serpent TMS

### 2. Основные соглашения хранения данных

&nbsp;Перед началом использования программы очень важно понимать в каком блоке какая информация должна храниться, чтобы не возникало конфликов внутри программы, связанных с нессотвествием размеров и типов данных. Перед начаом моделирвоания обязательно нужно создать два объекта: **Массив с историями нейтронов** и **Среда**. Для этого достаточно согдать типы данных: `type(netron_data)` и `type(enviroment)`. Первый созаднный объект будет использоваться для храненениия всех изменений происходящих с этим нейтроном в течение выполнения программы, второй создает среду, который настраивается один раз в начале программы.

&nbsp;При работе с нейтронной историей важно помнить:
* **координаты** нейтрона измеряются в **см**
* **скорость** нейтрона измеряется в **м/с**
* **Энергия** нейтрона измеряется в **эВ**
* **Время змаедления** нейтрона измеряется в **сек** 

Остальная информация о хранение и использвоание истории нейтрона описана в прошлом разделе.

&nbsp; Более сложной для настройки, систематизации и использования данных является объект среды. Так как одновременно нужно хранить и использовать большие блоки информации. Разберемся с тем, как устроено хранение информации, а использование будет описано далее.

&nbsp; При создание файла среды необходимо  
1. Задать темпретаурную сетку
2. Установить начальную температуру среды
3. Добавть ядра в среду
4. Настроить информацию о каждом ядре (ввести основные данные о нем и сохранить сечения)
5. При использование настроить библиотек OTF

Важно понимать, как устроено хранение информации о сечениях. В каждом нуклиде отдельно вложено два массива, в первом хранится сетка энергий сечения, во втором массиве производных типов данных сохраняется индекс реакции и массив сечений по температурам (в соотвествие с температрурной сеткой в среде). Хранение данных в массиве осщественно по следующей схеме
```text
              __Индекс температуры
             |
    tem_grid(t)
        |                      __Индекс энергии
        |                     |
        energy_point_in_table(e)
                    ___Индекс реакции
                   |
        cross_data(r)
            |
            |
            cross_section_point_in_table(e;t)
    
```
Аналогично реализовано хранение коэфициентов для библиотеки OTF, однако данный алгоритм требует создания уникальной энергетической сетки, которая бы подходила ко всем реакциям одновременно. Схема работы с массивом K_OTF:

```text
                 __Индекс энергии
                |
    e_uniq_grid(e)
             ___Индекс реакции
            |
    K_OTF(e,r,c)
              |__Индекс коэффициента
```
### 3.Математический аппарат

&nbsp;Математический модуль в данной программе очень простой и включает в себя всего три функции.
* Интегрирование функции
* Генерация случайной величены по заданной плотности вероятности 
* Генерация случайынх чисел

> **Интегрирование** —  
Реализовано с помощью функции *integrate_function*

| IN        	|          	|                            	|
|-----------	|----------	|----------------------------	|
| поле      	| тип      	| смысл                      	|
| f         	| function 	| функция для интегрирвоания 	|
| left_lim  	| real     	| левая граница              	|
| right_lim 	| real     	| правая граница             	|
| n         	| integer  	| количество разбиений       	|
| OUT       	|          	|                            	|
| res       	| real     	| результат интегрирвоания   	|

Интегрирвоание необходимо для реализации второй функции - поиск случайной величены по заданой плотности вероятности. Для этого сначала нужно вычислить функцию распределения, которая подразумевает вычсиление интеграла.

> **Генерация случайного числа** —  
Реализовано с помощью функции *get_random_in_range* - функция принимает максимально и минимальное значение интервала выбора сулчайно величины, а возвращает случайное число с интервала 

В данном модуле есть одна, связанная с передачей температуры среды и массы ядра, она производится с помощью функций `get_mass` и `get_temp`, в которые непосредственно подается масса и температура и таким образом реализована настройка модуля под данные характеристики.

### 4. Формат файлов сечений взаимодействия

1.  `name_of_nuclie` - имя нуклида
2.  `index_of_nuclie` - индекс нуклида, по которму программа обращается к нему

5.  `count_process` - количество процессов
6.  `count_point` - количество точек в таблице
7.  массив `index_of_process` для всех процессов

### 7. Обработка доплеровское уширение сечений 
 
&nbsp; Табличные сечения чаще всего построены при нулевой температуре, то есть при случае, когда ядра находятся в покое. Следовательно при измененеие температуры среды сечения взаимодействия становятся неверными, так как теперь при учете вероятности взаимодействия нужно рассматрвиать не сечения в зависимости от энергии, а сечения от относительной энергии нейтрона с ядром мишенью, однако эта энергия может быть разной в зависимости от скорости ядра, так как она распределена в соотвествтие с законом Максвела. Поэтому необходимо сгенерировать эффективные сечения, при подстановке которых в формулу для скорости взаимодействия полчался бы верный результат, в нынешней программереализовано три метода учета доплер эффекта.  

**7.1 Алгоритм SIGMA_1**  

Данный алгоритм позволят точно вычислить эффектиное сечение, поэтому сечения рассчитаные в данном методе будет считать реперным. В программе данный модот осуществлен модулем `DoplerTrearmentNJOY`, основная функция `doplerBroadr` вызывает `sigma_star`, а `sigma_star` использует `compute_H_all` и рекуррентную функцию `Fn`

| IN            	|         	|                               	|
|---------------	|---------	|-------------------------------	|
| поле          	| тип     	| смысл                         	|
| `currentEnergy` 	| `real`    	| нынешняя энергия              	|
| `E`             	| `real(:)` 	| массив температурной сетки    	|
| `sigma`         	| `real(:)` 	| массив сечений взаимодействия 	|
| `alpha`         	| `real`    	| коэфициент                    	|
| `n`             	| `integer` 	| количество процессов          	|
| OUT           	|         	|                               	|
| `res`           	| `real`    	| уширенное сечение             	|

В данную функцию темпера подается вместе с коэфициентом, который вычисляется следующим образом 
```Fortran
alpha = env%different_tipe_of_nuclear(i)%mass_of_nuclear/(k*tem)
```
Именно данная модуль используется для получения дополнительных файлов с сечениями, в котороых хранится их температурная зависимость.

**7.2 Алгоритм MCNP**  

&nbsp;Следующий алгоритм осуществляет учет температурной зависимости сечений с помощью библиотеки **OTF (On-The-Fly)**. Основная идея метода в текущей программе заключается в том, чтобы не вычислять полное доплеровски уширенное сечение функцией `doplerBroadr` при каждом обращении во время транспорта. Вместо этого на этапе подготовки библиотеки строится специальная энергетическая сетка, для каждой точки этой сетки вычисляется зависимость сечения от температуры, после чего данная зависимость аппроксимируется набором коэффициентов. Во время самого транспортного расчета программа должна только найти нужную энергетическую точку в OTF-библиотеке, выбрать коэффициенты нужной реакции и восстановить сечение функцией `eval_expansion`.

&nbsp;В программе OTF-алгоритм разделен между несколькими модулями:

* `MCNPconfigOTF` — хранит параметры построения библиотеки;
* `Dopler_MCNP_OTF` — строит температурные сетки, адаптивную энергетическую сетку и коэффициенты;
* `operation_with_data` — считывает уже подготовленные OTF-файлы;
* `process_manager` — осуществляет поиск по загруженной OTF-библиотеке в функции `get_sigma`.

```text
    исходные сечения
          |
          v
    doplerBroadr
          |
          v
    Dopler_MCNP_OTF
          |
          |--> build_temerature_grid
          |--> build_union_grid
          |--> build_coefficients
          |--> fit_one_energy
          |--> least_squares_svd
          |
          v
    OTF library
          |
          |--> unique-energy-grid-*.txt
          |--> coefficients-MT-*.txt
          |
          v
    operation_with_data
          |
          |--> load_unique_energy_grid
          |--> load_OTF_coefficients
          |
          v
    e_uniq_grid + K_OTF
          |
          v
    eval_expansion
          |
          v
    sigma(E,T)
```
Для каждого нуклида библиотека состоит из двух частей:

1. `unique-energy-grid-<Nuclide>.txt`;
2. набора `coefficients-MT-<Reaction>-<Nuclide>.txt`.

Для Carbon:

```text
CoefData/unique-energy-grid-Carbon.txt
CoefData/coefficients-MT-1-Carbon.txt
CoefData/coefficients-MT-2-Carbon.txt
CoefData/coefficients-MT-102-Carbon.txt
```
Для загрузки библиотеки OTF из фалов используется функция `load_OTF_coefficients`

Рассмотрим соглашения по хранению данных библиотеки OTF.  
* Каждая строка в файле с уникальной сеткой энергий содержит одно значение энергии:

```text
0.000010
0.000011
0.000012
0.000013
...
```

После загрузки:

```Fortran

```

соответствует строке `i`.

```text

строка 2 -> e_uniq_grid(2)
...
строка N -> e_uniq_grid(N)
```

* Формат файла с коэффициентами следующий


```text
index energy C1 C2 C3 ... C17 error
```

Пример структуры:

```text
1 1.000000E-05 C1 C2 C3 ... C17 2.3E-04
```

коэффициентс сохраняются в соотвествие с энергией и типом реакции (как описывалось ранее)

```Fortran

```

Как ранее говорилось библиотека OTF состоит из двух частей: **уникальная энергетическая сетка** и **таблица с коэффициентами**.

Программа поддерживать два режима работы, как содание библиотеки с данными, так и чтение уже готовой библиотеки из подготовленных заранее файлов. чтение осуществляется с помощбю функции

**7.3 Алгоритм TMS** 

&nbsp;Третий способ учета температурного движения ядер основан на **Target Motion Sampling**. В отличие от SIGMA_1 и OTF, здесь не строится отдельная полная библиотека горячих сечений для каждой температуры. Вместо этого непосредственно во время  работы программы вычисляются мажорантные сечения и в послдствие используются вместо обычных, далее столкновение с учетом выероятности либо принимается, либо нет. То есть при работе программы исполбзуется только один тип сечений, расчитанных в условиях 0 температуры.

| OUT |  |  |

| `target_velocity(3)` | `real` | скорость ядра |

Так как данный метод представляет из себя алгоритм рассчета, то есть нет готовой функции соотвественно сечение не находится, поэтому представим алгоритм реализованный в программе.

1. Сначала для каждого нуклида строится сетка, в которой каждой энергии отвечает свое мажорантное сечение, определяемое формулой, описанной немного ранее
2. Далее разыгрывается пройденное расстояние по формулам в самом начале (с учетом направления прибавляется к прошлому вектору движения)
3. Следующим шагом выбирается нуклид взаимодействия с помощью случайного числа

4. После выбора реакции семплируется скорость ядра-мишени с помощью распределения P1.
5. Далее проверяется выполнимость реакции с помощью случайного числа, определенного на этапе розыгрыша пройденного расстояния
6. Если неравенство пятого пункта не выполнено, тогда алгоритм выполняется со второго пункта заново
7. Если неравенство верно, тогда происходит выбор реакции по случайному числу

### 14.Оцениватели скорости реакции  
Оцениватель скорости реакции играет очень важную роль, так как он позволяет расчитать поток нейтронов или скорость той или иной реакции. Очень удобным для реализации является оцениватель по пройденному растояни, однако у него есть ограничения, например нельзя его использовать при непрерывно меняющейся с пространством температурой или в неоднородных средах, однако в нашей программе температура меняется дискретно, поэтому использования данного оценивателя обосновано. Однак все равно в программе доступна реализация доплер эффекта с помоью TMS, посколько сечение напрямую в методе не вычисляется использование данного оценивателя стнаовится невозможным, поэтому в программу добавлен оцениватель по столкновениям.

Начисляются оцениватели в отдельное поле в истории нейтрона `speed_estimator`, если работает метод TMS в нее загружается оцениватель по столкновению после столкновения, иначе по пройденному растоянию.
Запишем формулу вычисления для каждого оценивателя:

**14.1 Оцениватель по пройденному растоянию** 

```Fortran
path =
sqrt((new_x-old_x)**2 + (new_y-old_y)**2 + (new_z-old_z)**2)
```

Затем:

```Fortran
new_netron_data%speed_estimator = path * mic_current_cross_section_mas(2)
```

**14.2 Оцениватель по столкновениям**  

```Fortran
new_netron_data%speed_estimator =
    g_local *
    found_cross_section_from_energy( &
        Eprime,294.0,env,nuclide,2) *
    nuclear_dencity /
    total_mac_cross_section
```
